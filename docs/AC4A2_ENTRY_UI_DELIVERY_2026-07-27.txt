--------------------------------------------------------------------------------
5. DESIGN NOTES / DELIBERATE CHOICES
--------------------------------------------------------------------------------
  • default_tax_treatment is a SEPARATE field from tax_category (which drives the
    rate). It defaults to Auto (→ 'standard' at use) so existing behaviour is
    unchanged; it only matters for reverse_charge / export / out_of_scope, which
    tax_category can't express.
  • Per-line tax_treatment override was intentionally NOT added to the invoice
    line grid — the effective per-line treatment is DERIVED at e-invoice
    generation time via resolveLineTreatment(product, invoice) from the product
    default + the header is_export flag. A per-line override is a clean AC-4B/4D
    enhancement, kept out of the app's most critical editor for now.
  • invoice.place_of_supply_code is stored from the customer's place_of_supply on
    save rather than a second per-invoice dropdown, to keep the header uncluttered.
