1) MIGRATION FILE (deliverable)
--------------------------------------------------------------------------------
  supabase/migrations/20260722000002_phase53_h3_audit_logs_append_only.sql

  Effective statements (comments aside):

    ALTER TABLE public.audit_logs ENABLE ROW LEVEL SECURITY;   -- idempotent; already on

    DROP POLICY IF EXISTS tenant_isolation ON public.audit_logs;

    DROP POLICY IF EXISTS audit_logs_select ON public.audit_logs;
    CREATE POLICY audit_logs_select ON public.audit_logs
      FOR SELECT
      USING (company_id = current_user_company_id());

    DROP POLICY IF EXISTS audit_logs_insert ON public.audit_logs;
    CREATE POLICY audit_logs_insert ON public.audit_logs
      FOR INSERT
      WITH CHECK (company_id = current_user_company_id());

  No UPDATE policy and no DELETE policy are created -> both denied for
  authenticated / anon. postgres / service_role (BYPASSRLS) retain UPDATE/DELETE,
  so reset_company_data (SECURITY DEFINER) is unaffected.

  Properties:
    * Additive-style policy replacement on ONE table; no data row touched.
    * Idempotent: DROP POLICY IF EXISTS precedes each CREATE; safe to run twice.
    * Uses current_user_company_id() — the same tenant helper the old policy used.

3) ROLLBACK / UNDO INSTRUCTIONS
--------------------------------------------------------------------------------
  This change adds/removes NO data — it swaps policies — so "undo" means
  recreating the original policy. If it must be reverted, run in the SQL editor:

    DROP POLICY IF EXISTS audit_logs_select ON public.audit_logs;
    DROP POLICY IF EXISTS audit_logs_insert ON public.audit_logs;
    DROP POLICY IF EXISTS tenant_isolation  ON public.audit_logs;
    CREATE POLICY tenant_isolation ON public.audit_logs
      FOR ALL
      USING (company_id = current_user_company_id())
      WITH CHECK (company_id = current_user_company_id());

  This restores the exact prior state (single cmd=ALL tenant_isolation policy,
  read from live pg_policies before the change). Zero reconciliation risk in
  either direction because no audit row is created, modified, or deleted by
  either the migration or this undo.
