--------------------------------------------------------------------------------
1. WHAT THIS IS
--------------------------------------------------------------------------------
A pure, OFFLINE library that turns a StockBolt sales invoice (using exactly the
fields AC-4A/AC-4A.2 capture) into a compliant e-invoice payload:
  • India GST  → NIC/IRP e-invoice JSON (schema v1.1) — the IRN-request payload.
  • UAE        → PINT-AE (Peppol) UBL 2.1 Invoice XML.
It builds the payload only. It does NOT call any government API, sign, or make
an IRN/QR — that clearance step is deferred (GSP/ASP), by design.

2. FILES CHANGED (7 new, 0 modified)
--------------------------------------------------------------------------------
  NEW src/lib/einvoice/canonical.ts   Jurisdiction-neutral CanonicalInvoice +
        buildCanonicalInvoice(). Derives jurisdiction (IN_GST/AE_VAT from the
        supplier country), NIC supply type (B2B/B2C/EXPWP/EXPWOP/SEZWP/SEZWOP),
        place of supply (96 for export), intra-vs-inter-state, per-line CGST/SGST
        (even split, remainder-safe) vs IGST, and the UBL tax-category code
        (S/Z/E/O/AE). Reuses AC-4A resolveLineTreatment + isValidStateCode.
  NEW src/lib/einvoice/india-gst.ts   toIndiaGstJson(canonical) → NIC schema
        object (Version/TranDtls/DocDtls/SellerDtls/BuyerDtls/ItemList/ValDtls).
        ISO date → dd/mm/yyyy; PIN → number.
  NEW src/lib/einvoice/pint-ae.ts     toPintAeUbl(canonical) → UBL 2.1 XML string
        (Supplier/Customer party, TaxTotal with per-(category,rate) subtotals,
        LegalMonetaryTotal, InvoiceLine[]). Includes a tiny dependency-free,
        deterministic XML builder (stable ordering, 2-space indent, XML-escaped).
  NEW src/lib/einvoice/index.ts       Barrel re-export.
  NEW tests/unit/einvoice-canonical.test.ts   7 tests — allocation, export,
        supply-type + category mapping, AE jurisdiction, rounding split.
  NEW tests/unit/einvoice-india-gst.test.ts   4 tests — golden B2B intra-state
        payload (full toEqual), inter-state IGST, export EXPWOP, date/discount.
  NEW tests/unit/einvoice-pint-ae.test.ts     3 tests — byte-for-byte golden UBL
        for the standard case, zero-rated export (category Z), XML escaping.

  IMPORTANT re-affirmation: TAX IS NEVER RE-COMPUTED. Every monetary figure
  comes from the canonical, which took it from the posting engine. The CGST/SGST
  vs IGST "split" only ALLOCATES the tax the engine already calculated across the
  right heads (and the split is remainder-safe so the heads always re-sum to the
  line tax).

5. KNOWN LIMITATIONS (honest)
--------------------------------------------------------------------------------
  • Foundation fidelity: output is correctly STRUCTURED and locked by golden
    fixtures, but full field-level conformance to the official NIC schema / the
    PINT-AE XSD (and their validators) is iterative and needs the actual schema

    invoice/customer/company/product rows into CanonicalBuildInput happens in
    AC-4C/AC-4D (persistence + UI), keeping AC-4B pure and unit-testable.
