WHAT WAS DELIVERED
--------------------------------------------------------------------------------
  File: supabase/migrations/20260722000001_phase52_h2_one_canonical_per_source_index.sql

  It creates ONE partial unique index:

      CREATE UNIQUE INDEX CONCURRENTLY IF NOT EXISTS
        journal_entries_one_canonical_per_source
        ON public.journal_entries (company_id, source_type, source_id)
        WHERE source_id IS NOT NULL
          AND reversal_of_id IS NULL
          AND reversed_by_id IS NULL
          AND source_type IN (
            'sales_invoice',
            'vendor_bill',
            'sales_credit_note',
            'vendor_debit_note'
          );

  Nothing else is in the file except comments and a non-concurrent fallback.


WHY THE PREDICATE IS EXACTLY THIS (Option A)
--------------------------------------------------------------------------------
  The four source_types are the EXACT whitelist read from the live
  _guard_no_double_post trigger body (pg_get_functiondef):

      IF NEW.source_type NOT IN
        ('sales_invoice','vendor_bill','sales_credit_note','vendor_debit_note')
      THEN RETURN NEW;   -- unguarded types skip the check

  The trigger's own lookup filters on:
        reversed_by_id IS NULL AND reversal_of_id IS NULL
  The index reproduces that filter, plus source_id IS NOT NULL. So the index and
  the trigger enforce the IDENTICAL rule; the index simply makes it atomic
  (survives the concurrent-confirm race the trigger's read-check cannot).

  Because the index matches the trigger exactly it CANNOT reject any insert the
  trigger already permits -> it cannot break edit / void / repost:
    * a reversal MIRROR has reversal_of_id set  -> excluded
    * a voided/superseded canonical has reversed_by_id set -> excluded
    * re-confirming after a void inserts a fresh canonical while the old one is
      already reversed (excluded) -> allowed

  NOT covered (intentionally, unchanged behaviour): opening_balance, opening_bank,
  pos_sale, expense, and payment/receipt source_types are not in the trigger
  whitelist and are not in the index. (Covering them is Option B — out of scope.)
