## WHAT CHANGED, PER FILE
--------------------------------------------------------------------------------
  In each of the 4 editors:
    * The editable currency <Select> (which offered every world currency and
      wrote header.currency on change) was replaced with a disabled <Input>
      that displays header.currency read-only. header.currency still defaults to
      the company base currency (companyCurrency) and can no longer be changed.
    * The now-unused `currencyOptions` import was removed.
    * In quote-editor and vendor-bill-editor, the currency picker was their only
      <Select>, so the now-unused `Select` import was also removed (a direct,
      required consequence of the change to keep the build green).

  A one-line comment records why the field is locked (posting engine does not
  convert yet — see docs/MULTICURRENCY_AUDIT.md).


## EXACT REPLACEMENT (example — invoice editor)
--------------------------------------------------------------------------------
  BEFORE:
    <Select
      label={t('sales.currency')}
      options={currencyOptions(header.currency)}
      value={header.currency}
      disabled={!canEdit || isVoid}
      onChange={e => setHeader(h => ({ ...h, currency: e.target.value }))}
    />

  AFTER:
    <Input
      label={t('sales.currency')}
      value={header.currency}
      disabled
    />

## UI VERIFICATION CAVEAT
--------------------------------------------------------------------------------
  The 4 editors are auth-gated, so the read-only behaviour was verified by
  compile + build + code inspection rather than by driving the live UI (no
  credentials in this environment). The field is now a disabled input displaying
  the base currency, with no dropdown and no change handler — structurally it
  cannot produce a non-base currency. Recommended final check: open a new
  invoice on the dev server and confirm the Currency field shows the base
  currency (e.g. AED), greyed and non-editable.
